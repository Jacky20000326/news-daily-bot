# notebooklm-kit 資安評估報告

> 評估日期：2026-04-04
> 評估對象：`notebooklm-kit` (photon-hq/notebooklm-kit) v2.2.0
> 對照套件：`notebooklm-sdk` (agmmnn/notebooklm-sdk)
> 評估目的：該套件需傳入 Google 帳號憑證，評估是否有 token/密碼外洩風險

---

## 一、總結結論

### 核心發現：套件本身無惡意行為，但存在結構性風險

經原始碼審查，**兩個套件都沒有將憑證傳送至第三方伺服器**。所有 HTTP 請求僅發往 `notebooklm.google.com`，無遙測、無分析追蹤、無資料外洩行為。

然而，風險來自以下結構性因素：

| 風險等級 | 風險項目 |
|---------|---------|
| 🔴 高 | 非官方逆向工程 API，Google 可能封鎖帳號 |
| 🔴 高 | 憑證以明文儲存於本地檔案 |
| 🟡 中 | 套件維護者為小型/個人組織，供應鏈攻擊面較大 |
| 🟡 中 | 使用者基數小，安全漏洞可能未被發現 |
| 🟢 低 | 套件程式碼本身無惡意邏輯 |

## 二、原始碼審查詳情

### 2.1 認證機制

**notebooklm-kit 的認證流程：**

1. 讀取 `GOOGLE_EMAIL` + `GOOGLE_PASSWORD` 環境變數
2. 透過 **Playwright 啟動真實 Chrome 瀏覽器**
3. 在真實的 Google 登入頁面執行登入（非釣魚頁面）
4. 登入成功後從瀏覽器提取 session cookie 和 CSRF token
5. 將 token 儲存於本地 `./credentials.json` 或 `~/.notebooklm/session.json`
6. 後續 API 呼叫使用提取的 token，不再傳送密碼

**關鍵安全點：** 密碼僅在 Playwright 控制的真實 Chrome 中傳送給 Google 登入頁面，與你手動在瀏覽器登入 Google 的行為完全相同。套件不會將密碼發送至任何非 Google 的伺服器。

### 2.2 網路通訊

兩個套件的所有 HTTP 請求都僅發往以下 Google 網域：

```
https://notebooklm.google.com/_/LabsTailwindUi/data/batchexecute
https://signaler-pa.clients6.google.com/punctual/v1/refreshCreds（token 刷新）
```

**未發現任何對第三方伺服器的請求。**

### 2.3 依賴分析

**notebooklm-kit 的生產依賴僅兩個：**

| 依賴 | 版本 | 說明 | 風險 |
|------|------|------|------|
| `dotenv` | ^17.2.3 | 環境變數載入，業界標準 | ✅ 安全 |
| `playwright` | ^1.57.0 | Microsoft 維護的瀏覽器自動化 | ✅ 安全 |

**postinstall 腳本：** `npx playwright install chromium` — 僅安裝 Chromium 瀏覽器二進位，無惡意行為。

### 2.4 遙測與追蹤

**未偵測到任何遙測、分析或追蹤程式碼。**

### 2.5 程式碼混淆

**未偵測到任何混淆或壓縮。** TypeScript 原始碼完全透明可讀。

## 三、風險詳細分析

### 🔴 風險 1：Google 帳號封鎖風險

**描述：** 兩個套件都使用逆向工程的非官方 API。Google ToS 明確禁止自動化存取，Google 有權封鎖違規帳號。

**影響：**
- 帳號可能被暫時或永久停用
- 如果使用主要 Google 帳號，影響範圍包括 Gmail、Google Drive、Google Photos 等所有 Google 服務

**發生機率：** 中等。目前未有使用者回報因此被封鎖，但風險長期存在。

### 🔴 風險 2：憑證明文儲存

**描述：** 套件將 Google 密碼存放於 `.env` 檔案，session token 存於 `credentials.json` 或 `~/.notebooklm/session.json`，均為明文。

**影響：**
- `.env` 誤提交至 Git → 密碼外洩
- 伺服器被入侵 → 攻擊者可讀取明文憑證
- CI/CD 環境變數日誌意外記錄密碼

**發生機率：** 取決於操作紀律。使用不當時機率高。

### 🟡 風險 3：供應鏈攻擊

**描述：** `photon-hq` 為小型組織（33 stars、2 forks），如果：
- 維護者帳號被駭，攻擊者可發布含惡意程式的新版本
- npm 發布的版本理論上可能與 GitHub 原始碼不同

**影響：** 惡意版本可能竊取環境變數中的所有憑證。

**發生機率：** 低，但非零。這是所有小型 npm 套件的通病。

### 🟡 風險 4：API 突然失效

**描述：** Google 任何時候都可能更改 NotebookLM 的內部 API 端點、請求格式或認證機制。

**影響：** Podcast 生成功能突然失效，需等待套件維護者更新。

**發生機率：** 高。逆向工程 API 本質上不穩定。

## 五、緩解措施建議

### 若決定採用

1. **建立專用 Google 帳號**
   - 不要使用主要 Google 帳號
   - 建立一個僅用於 NotebookLM 自動化的新帳號
   - 該帳號不綁定任何重要資料（Gmail、Drive 等）

2. **使用 Google App Password**
   - 不要直接使用 Google 帳號主密碼
   - 在 Google 帳號設定中產生「應用程式密碼」
   - App Password 可隨時撤銷，降低洩漏影響

3. **鎖定套件版本**
   - `package.json` 中使用精確版本號（去掉 `^`）
   - 避免自動更新到可能被植入惡意程式的新版本
   - 更新前手動審查 changelog 和 diff

4. **憑證安全**
   - `.env` 加入 `.gitignore`（已做到）
   - 生產環境使用 secrets manager（如 GitHub Secrets、Vault）
   - 定期輪換 App Password

5. **監控**
   - 定期檢查專用 Google 帳號的登入活動
   - 設定 Google 帳號安全警示通知

### 若不採用的替代方案

| 替代方案 | 安全等級 | 說明 |
|---------|---------|------|
| Google Cloud Podcast API（官方） | ✅ 最高 | 需企業授權，使用服務帳號認證，無帳號封鎖風險 |
| Gemini 腳本 + 第三方 TTS | ✅ 高 | 不碰 Google 帳號，用 API Key 認證 |
| 維持現有 Gemini TTS | ✅ 高 | 零額外風險，但為單人語音 |

## 六、報告內容上傳至 NotebookLM 的資料隱私風險

前面的章節聚焦於「套件是否安全」，但還有一個同樣重要的面向：**你的報告內容上傳到 Google 伺服器後會怎樣？**

### 6.1 Google 是否會用你的資料訓練 AI？

| 帳號類型 | 用於 AI 訓練？ | 人工審查？ |
|---------|--------------|-----------|
| 免費個人帳號 | ❌ 不會（除非你主動點「讚/踩」回饋） | ⚠️ 僅在你提供回饋時可能被審查 |
| Google Workspace | ❌ 不會 | ❌ 不會 |
| Enterprise | ❌ 不會 | ❌ 不會 |

**結論：** 即使用免費帳號，你的報告內容預設不會被拿去訓練 AI。但如果你在 NotebookLM 介面上點了「讚/踩」回饋，該筆互動可能被 Google 人工審查。

> 由於我們是自動化流程（建立 → 生成 → 刪除），不會觸發任何回饋機制，此風險極低。

### 6.2 資料保留與刪除

- **上傳的內容** — 儲存在 Google 伺服器直到你刪除 notebook
- **刪除後** — Google 文件未明確說明是否有寬限期或軟刪除機制，但刪除 notebook 後資料即移除
- **Audio Overview 音檔** — 同樣儲存至你刪除為止
- **對話記錄** — NotebookLM 的聊天查詢不會自動保存

**我們的自動化流程會在每次生成後立即刪除 notebook**，資料在 Google 伺服器上的存留時間僅為生成所需的 2-5 分鐘。

### 6.3 報告內容敏感度評估

你的加密貨幣日報內容包含：

| 內容類型 | 敏感度 | 說明 |
|---------|--------|------|
| 新聞標題與摘要 | 🟢 低 | 公開資訊，來自 NewsAPI、CryptoPanic 等公開來源 |
| AI 分析與評分 | 🟢 低 | 基於公開新聞的衍生分析，無商業機密 |
| 執行摘要 | 🟢 低 | 市場總覽，屬於一般性觀察 |

**結論：** 你的報告內容全部基於公開新聞來源的衍生分析，不含個人資料、商業機密或敏感資訊。即使資料被 Google 保留，造成的影響極低。

### 6.4 Playwright 瀏覽器的額外攻擊面

套件使用 Playwright 啟動完整的 Chromium 瀏覽器實例，這引入額外的攻擊面：

- **瀏覽器漏洞** — Chromium 本身可能存在未修補的安全漏洞
- **記憶體中的憑證** — 登入期間密碼和 session token 存在於瀏覽器程序的記憶體中
- **Headless 模式風險** — 在伺服器環境中以 headless 模式運行瀏覽器，若伺服器被入侵，攻擊者可從程序記憶體中提取 token

**緩解：** 使用專用帳號 + App Password，即使 token 被提取，影響僅限於該專用帳號。

### 6.5 自動化登入觸發 Google 安全機制

Google 會偵測異常登入行為：

- **不同 IP/地理位置** — 從伺服器 IP 登入可能觸發安全警告或要求額外驗證
- **頻繁登入** — 每日自動登入可能被標記為可疑行為
- **Headless 瀏覽器指紋** — Google 可能偵測到自動化瀏覽器並封鎖登入

**可能後果：** Google 帳號被鎖定、要求手機驗證、或直接封鎖。使用專用帳號可限制影響範圍。

## 七、完整風險總覽

| 風險類別 | 風險項目 | 等級 | 影響 |
|---------|---------|------|------|
| **套件安全** | 憑證外洩至第三方 | 🟢 低 | 經審查未發現，所有請求僅發往 Google |
| **套件安全** | 供應鏈攻擊（惡意更新） | 🟡 中 | 鎖定版本可緩解 |
| **帳號安全** | Google 封鎖帳號 | 🔴 高 | 使用專用帳號可限制影響 |
| **帳號安全** | 憑證明文儲存被竊取 | 🟡 中 | App Password + secrets manager 可緩解 |
| **帳號安全** | Google 安全機制阻擋自動化登入 | 🟡 中 | 可能導致功能失效，fallback 至 TTS |
| **資料隱私** | 報告內容被 Google 保留 | 🟢 低 | 內容為公開新聞衍生，刪除後即移除 |
| **資料隱私** | 報告內容用於 AI 訓練 | 🟢 低 | Google 政策明確不會（除非主動回饋） |
| **運行環境** | Playwright 瀏覽器攻擊面 | 🟡 中 | 伺服器安全性需確保 |
| **穩定性** | API 變動導致功能失效 | 🔴 高 | 保留 TTS fallback |

## 八、最終建議

**如果 Podcast 品質是硬需求且願意承擔風險：**
→ 採用 `notebooklm-kit` + 專用 Google 帳號 + App Password + 版本鎖定
→ 你的報告內容為公開新聞衍生，資料隱私風險極低

**如果資安優先級高於 Podcast 品質：**
→ 改用「Gemini 生成對話腳本 + Fish Audio/Google Cloud TTS 多語音合成」方案
→ 完全避開 Google 帳號憑證、資料上傳、帳號封鎖等所有風險

**長期方向：**
→ 關注 Google Cloud Podcast API 的公開可用性，一旦開放個人版即遷移至官方 API
